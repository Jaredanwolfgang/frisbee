# Tiga战术库

球队内部使用的精简战术与 Drill 工具：<https://jaredan.site/frisbee/>。部署在 Aliyun-RMMT 的 `/root/frisbee`，代码仓库为 `git@github.com:Jaredanwolfgang/frisbee.git`。

## 使用

- 队友打开网址即可查看服务器里的战术，无需登录。
- 在更多菜单中点击“开启编辑”并输入编辑口令，可新建、编辑、导入或删除战术；点击“保存”后，其他设备重新打开即可看到。已打开的页面每 20 秒检查一次更新；编辑未保存草稿时暂停刷新。
- “复制链接”会先保存当前修改，再复制 `#tactic=...` 链接，直接打开对应战术，不包含编辑权限。
- 修改采用版本检查。若队友已保存了新版本，会提示将当前草稿另存为副本，保留双方内容。
- 旧浏览器的自建、修改过的战术会显示“上传旧战术到服务器”。需要编辑权限，原浏览器备份继续保留；同编号、不同内容会另存副本。
- 没有账号和个人收藏；用名称、标签、说明和各步骤的执行要点搜索，按战术 / Drill 和分类筛选。
- 新建 Drill 可先选 1–7 名演示队员（含防守），普通战术每方最多 7 人。人数调整会应用所有步骤，删除队员会清理相关路线，可撤销。
- 手机可新建、拖动排站位，也可点选队员、再点终点绘制路线。名称、说明、标签等可稍后补充。
- 「角标」工具可点击场地添加锥桶标记，拖动调整，点选后命名或删除；支持撤销、方向键微调和 Delete 删除。每套最多 32 个角标，全部步骤共用，独立于队员人数限制，随战术保存到服务器、导出和分享。
- 手机战术板支持全屏横屏；不支持原生全屏时使用页面内旋转布局。

## 界面与规则查询

- 顶部切换「Tiga战术库 / WFDF」，分别保留两种模式的查询。战术以场地图 Gallery 展示；主页不显示编辑按钮和同步状态，编辑入口保留在「···」更多菜单中。
- 手机打开战术默认查看，点「编辑」才启用绘图和人数调整；新建草稿直接进入编辑。播放栏固定在页面下方，选中队员或弧线不会改变场地尺寸。详情独立整页阅读，保存后返回查看。
- 模式切换和规则 AI 入口兼容触摸/点击事件；非模态问答页不锁住主界面的点击，页面恢复时清理残留状态。若脚本未完整启动，顶部会显示错误提示和重新加载入口。
- 手机 AI 问规则使用整页对话，返回后保留聊天；条款引用在回答内展开，长条文可进入全文页后返回。浏览器返回键逐层退出全文、详情、编辑或新建步骤；未保存修改离开前可继续编辑、保存或放弃。分享、编辑解锁和删除确认使用底部短面板。
- 手机输入框保持 16px 字号，输入区域随可见视口调整；保留原生缩放和横屏全屏。桌面继续使用战术编辑器和规则问答底部窗口。
- 打开战术，顶部「···」可删除已存在的战术或手动复制专属链接。删除需编辑权限和确认，在服务器保留软删除记录。
- WFDF 规则为本站保存的文字，按中文、英文、条款号和章节搜索；来源和章节作为搜索栏内的限定，常用标签放在下方。空搜索先显示章节目录；结果按小节连续阅读，保留条款层级、条件和例外，统一切换中英对照。版本与来源通过右上角 ⓘ 查看，不嵌入或部署 PDF。
- 相关查询显示 WFDF 官方 24 种手势图和 14 张开盘情形图；点击缩略图放大阅读，开盘图保留飞行/滚动/轴心图例。标签「手势图」可浏览全部手势；图片本地保存，来源记录在 `dist/wfdf/visuals.json`。
- 正文 2025–2028 共 368 条，中译文 367 条（官方中译本缺少 19.2.1.1，显示英文）；含名词定义和 2026-06-01 生效的 147 项官方注释。
- 英文正文与注释提取自 WFDF 官网链接的 URules HTML，排除站长个人评论。HTML 附录存在编号/版本差异，本站附录使用 WFDF 现行 v2.0 的文字，保留表格所在页的文字排版。图示请通过官方来源核对。
- 来源、译者、CC BY 4.0 及整理方式见 `dist/wfdf/NOTICE.txt` 和规则页「版本与来源」。核对日期 2026-10-25；无自动更新承诺。

规则索引的维护（需要 Poppler 的 `pdftotext`，无第三方 Python 库）：从 `index.json` 中的官方来源下载四份原始文档到站点目录外，使用 `rules-en.pdf`、`rules-zh.pdf`、`annotations-en.pdf`、`appendix-en.pdf` 文件名；下载 `https://urules.org/all.html` 到临时文件。随后执行：

```bash
WFDF_SOURCE_DIR=/path/to/source-documents python3 -B scripts/build-rules-index.py
python3 -B scripts/import-rules-html.py /path/to/urules-all.html
node scripts/verify-rules.cjs
```

官方图解资产可使用 Poppler 按源文档版面重新导出（PDF 仍只作为外部输入）：

```bash
python3 -B scripts/build-rule-visuals.py /path/to/hand-signals.pdf /path/to/pull-diagrams.pdf
```

需要在源文件更新时人工检查所有裁切边界、图例和条款对应关系，不能把静态示意当成动作视频。

两步导入会核对 20 章、368 条及中英对应情况；需在更新版本时人工检查 HTML 与官方文档差异、注释版本和附录版本，并更新日期、来源与验证。原始 PDF 和第三方 HTML 不进入部署包，运行时无需抓取外站。

## 盘队中心（比赛、训练与个人看板）

- 左上角固定显示奥特曼图标和 Tiga，旁边的工作区下拉菜单提供「战术库 / 懂WFDF / 盘队中心」。切换时品牌位置不变，搜索内容各自保留；支持触摸、方向键、Enter、Escape 和 Tab。盘队中心包含看板、比赛、训练、队员四栏；入口为 `#team`，子页为 `#team/games`、`#team/trainings`、`#team/players`，旧 `#stats`、`#trainings` 仍兼容。查看公开；记录与名单管理沿用编辑会话。右上角顺序固定为「开启编辑 / 管理中」，再是「队员登录 / 头像」。
- 队员使用盘名或唯一号码及个人口令登录，进入个人看板；仍可切换全队总览。登录不授予管理权限，管理会话也不代替队员身份。口令由管理员初始化或重置，至少 8 位，存储为随机盐 PBKDF2-SHA256（600000 次）摘要。队员可在个人资料中使用当前口令修改自己的口令。重置后旧队员会话立即失效；旧版只凭盘名的会话不再接受。现有队员资料与历史记录保留，首次使用需管理员设置个人口令。
- 「管理队员」维护盘名、号码（0–99，号码不重复，名单上限 40 人）、入队日期、个人口令和性别（男/女，记录页与统计表显示 ♂/♀）；未删除比赛中仍有该队员记录或上场阵容的不能删除，删除比赛后即可删除队员。
- 「新建比赛」填写比赛名称和对手队伍名称，可选填比赛录像链接（文本超链接，http(s):// 开头，缺协议头时自动补 https://）；之后可在「···」菜单里随时修改名称、对手和录像链接，比赛页顶部显示「▶ 比赛录像」入口。实时记录页按分记录：点「新的一分」选择进攻开 / 防守开并点选上场队员（自动预选上一分阵容），确认后记录传盘；得分即结束当前分。点内流程：点选持盘人，再点接盘人，按「传盘完成 / 得分 / 失误 / D 防守成功」记录。传盘完成后接盘人自动成为持盘人；只选持盘人直接失误记为传丢，选了接盘人的失误记为接盘掉盘；D 防守成功只选防守队员。每次记录立即上报服务器，可撤销上一条；比赛可结束、重新开始和删除（软删除，删除后不再限制队员删除）。
- 赛后讨论与训练讨论：队员登录后可以多次发言、回复主评论并显示当前头像；只能编辑、删除自己的评论，删除后可恢复。历史心得保留为主评论。每条最多 800 字，每场讨论最多 400 条（含已删除项）。个人看板从讨论中识别是否参与心得。场均数据与正式比赛/训练赛隔离保持不变。
- 手机端比赛记录采用整页布局，分为「实时记录 / 本场数据 / 逐分记录 / 赛后总结」。录入操作区固定在底部；队员区域独立滚动并支持盘名、号码搜索，默认显示本分阵容，也可展开全部名单。新建比赛直接选择首分阵容；确认或取消阵容选择后清除搜索条件。盘队中心首页使用个人或全队看板，场均与本场数据按进攻、失误与防守成功、上场分组查看；全部指标可横滑并保留左侧姓名。队员管理、新建比赛和队员登录在手机上使用整页表单，输入字号至少 16px，提交区适配键盘可见范围；电脑端保留完整统计表和比赛各区。
- 存储与战术共用 `data/playbook.sqlite3`（`stats_players` / `stats_games` / `stats_events` / `stats_comments` 表与 `stats_revision`，旧库自动补齐新列）。`GET /api/stats?revision=N` 支持小轮询（页面在统计模式每 8 秒核对一次）并返回 `me` 身份；写接口与战术一致要求同源校验和长度限制，管理类操作要求编辑权限，总结要求队员身份。

编辑登录可在服务器私有 `.env` 设置 `EDITOR_PASSWORD`（至少 8 字符），与用于 Cookie 签名的随机 `EDITOR_KEY` 分开；未设置时保持原来的密钥登录。更换口令时同时轮换签名密钥，使旧编辑会话失效；队员总结登录也需重新进行。两项均不得提交到仓库。

## 训练

- 训练归入盘队中心「训练」栏目（`#team/trainings`，旧 `#trainings` 仍可用）。训练场次的管理沿用编辑会话，查看公开；与统计共用队员名单和登录身份。
- 每次训练包含四部分：**出勤**（点选队员后保存，计入出勤率）、**热身**（文本计划，可随时修改）、**Drill**（从战术库的 Drill 中选择，最多 20 个，可移除）、**训练总结**（与赛后总结相同：登录队员每人一条，可修改或删除）。
- 训练页内可添加**训练赛**：记录模块与正式比赛完全相同（逐分阵容、传盘、得分、失误、防守成功、录像链接、赛后总结），但训练赛不出现在正式比赛列表，也不计入场均数据。
- 场均数据表新增**出勤率**列：按已完成且日期已到、处于队员入队日期之后的训练计算（出勤次数 / 应参加次数；入队日期留空包含全部历史），与其他指标一样点击表头可正序 / 倒序排序；该列在任意指标视图下保持可见。
- 存储为 `stats_trainings` 表，训练赛通过 `stats_games.training_id` 关联，总结复用 `stats_comments`（新增 `training_id` 列）。旧库启动时自动迁移：补齐新列，并重建带 `game_id NOT NULL` 旧约束的 `stats_comments` 表以支持训练总结。

## 加载与同步

- 发布时从同一 Git 提交生成 `dist/assets/<内容版本>/`，按入口顺序将主脚本合并为单个文件以减少首屏请求，启动错误提示独立加载，浏览器长期缓存这些不可变资源；入口 HTML 仍检查更新。旧版本资源保留，避免已打开页面请求失效。
- 浏览器只读保存最近一次公开战术列表，再次打开先显示上次内容并提示正在同步；首次核对仍取完整服务器数据，不缓存编辑权限或凭证。服务器继续作为所有增删改的来源。
- 在线同步使用修订号；内容未变时只返回版本及当前权限，不重复下载整套战术或重建 Gallery。离线、缓存损坏或浏览器禁用存储时仍可直接走服务器加载。
- 更多菜单中的「速度诊断」显示当前设备的页面、首次战术同步、原文返回及 AI 首字/总耗时；仅在当前页面记录，不自动上传，也不记录问题或凭证。
- AI 保持原有流式服务和条款校验，前端按显示帧合并文字更新，减少手机上的排版和滚动开销；模型与网络等待仍以实际链路为准。

## 服务与数据

- `dist/`：无构建依赖的 HTML、CSS、JavaScript，包括战术图编辑、动画和教学示例。
- `server/app.py`：Python 标准库 HTTP API、SQLite 数据库，头像处理使用 Pillow。
- `server/seed.json`：仅用于初始化的公开示例。运行 `node scripts/build-seed.cjs` 从前端示例生成稳定种子。
- `compose.yaml`：现有 `rmmt-net` 内的 Nginx 和 Python 服务，不额外暴露主机端口。
- `data/playbook.sqlite3`：持久化战术、版本和删除记录。服务器更新不得覆盖此目录。
- `.env`：编辑口令和访问配置，权限为 600，禁止提交 Git。

写入接口要求编辑会话或编辑 key；浏览器使用 HTTPS 的 HttpOnly、SameSite=Strict Cookie。会话有效期为 7 天。队友只需查看链接；仅向需要编辑的人提供编辑口令。更换 `EDITOR_KEY` 并重新创建 API 容器可撤销已有会话。

## HTTPS 证书与续期

`jaredan.site`、`www.jaredan.site`、`rmmt.jaredan.site`、`admin.jaredan.site` 共用服务器上的同一份 Let’s Encrypt 证书。主代理为 `rmmt-proxy`，宿主机 Certbot 的现有 `certbot.timer` 负责定期续期。证书、私钥和 ACME 账户仅保存在服务器 `/etc/letsencrypt`，禁止提交 Git。

使用 `webroot` 验证，避免旧的 `standalone` 验证与现有代理争用 80 端口：HTTP 的 `/.well-known/acme-challenge/` 只映射 `/etc/letsencrypt/webroot` 下的公开验证文件，其余域名 HTTP 请求继续跳转 HTTPS。现有容器已经只读挂载 `/etc/letsencrypt`，无需增加端口或停止代理。

```bash
bash scripts/repair-tls.sh Aliyun-RMMT
```

脚本适用于当前已到续期时间的证书：先在 `/root/frisbee/backups/tls-*` 备份代理配置和续期配置，只修改已识别的域名 HTTP 跳转块，保留文件 inode 和其他应用路由；验证 Nginx 配置并热加载，实测四个域名的 HTTP-01 验证路径后，续签同一份证书。成功续期会保存 Webroot 配置。

服务器的 `/etc/letsencrypt/renewal-hooks/deploy/40-reload-rmmt-proxy` 在续期后先执行 `nginx -t`，再热加载代理。脚本最后通过 `--dry-run --run-deploy-hooks` 测试保存的续期配置与加载钩子；测试证书不会替换正式证书。若证书尚未进入续期窗口而需要首次更改验证方式，应使用 `certbot reconfigure --cert-name jaredan.site --authenticator webroot --webroot-path /etc/letsencrypt/webroot` 并核对结果。

完成后用正常证书验证检查四个域名的线上有效期、主站与 `/frisbee/api/health`；不要使用跳过 TLS 校验的参数掩盖故障。主代理配置位于已有的 RMMT 工作区，修复脚本会保留其未提交改动，不会替该工作区提交或推送。

## 备份与恢复

每次代码部署前，会把数据库一致性快照保存到服务器 `/root/frisbee/backups/`。页面也支持导出 JSON 战术备份。数据库包含软删除记录，种子初始化不会复活删除的战术。

恢复数据库时先停止 `frisbee-api`，将确认过的 SQLite 备份恢复到 `data/playbook.sqlite3`，处理对应的 WAL/SHM 文件并恢复目录所有权，再启动 API。恢复会回退整个团队库，执行前先另存当前数据库。

基础阵型与防守概念参考 USA Ultimate、UGA 教材；场上路线为可编辑教学示例，按球队口令及实际防守调整。

## DeepSeek 文字助手

AI 密钥只配置在服务器 `.env` 的 `AI_API_KEY`，不会发送到浏览器或进入 Git。当前使用同一服务器已有的 DeepSeek 账户；`AI_BASE_URL=https://api.deepseek.com`，规则问答使用 `AI_RULES_MODEL=deepseek-flash`，战术整理使用 `AI_TACTIC_MODEL=deepseek-v4-pro`。模型名需按账户 `/models` 实际支持情况核对，不能依赖旧的 `deepseek-chat` 名称。本阶段仅支持文字。

“新建”里的文字入口或更多菜单中的“AI 生成战术”需要编辑权限。描述与人数设置交给模型整理为传跑计划；服务端根据连续盘权和队员位置编译步骤，校验人数、坐标、持盘跑动、接盘终点与角标。关键动作不清楚时先返回澄清问题。结构校验不能保证模型完全理解教练意图，因此先展示说明、绘图约定与步骤预览，再打开未保存的战术板，由教练核对后点击保存；生成接口本身不写入团队数据库。

WFDF 的“AI 问规则”支持连续追问。服务端从部署的本地规则、官方注释、附录及手势索引检索，先通过 SSE 发送原文与手势，再流式解释；整组条款及其例外一起送入上下文。解释中的条款号必须存在于本次检索结果，否则界面隐藏该次解释并提示核对原文。引用校验不等于事实裁定，信息不充分时应结合原文条件补充情形。赛事附录仅在本场采用时适用。模型不会自行抓取网站。

规则问答公开可用，战术生成沿用编辑会话；均校验同源请求、限制请求长度、并发 3、每 IP 每分钟 12 次。默认总额度每小时 200 次，可通过 `AI_HOURLY_LIMIT` 调整。对话仅保留在当前页面内存中，服务端不保存对话记录；提问和相关规则正文会发往配置的 DeepSeek 接口。不要将密钥或个人敏感信息写入描述。

部署会只对主代理现有 `/frisbee/` 路由关闭响应缓冲、增加读取超时；`scripts/configure-ai-proxy.py` 在改动前备份、保留绑定文件 inode，并验证及热加载 Nginx。其余应用路由和 HTTPS 验证路径保持原有配置。内层代理同样关闭 AI 流式响应的缓冲。

本地无密钥时仍能手动画图和检索规则。测试用固定回复服务可在两个终端启动（不使用真实密钥，不应部署为线上模型）：

```bash
python3 -B tests/ai_fixture.py
env AI_API_KEY=local-fixture-only AI_BASE_URL=http://127.0.0.1:4176/v1 python3 -B scripts/dev.py
```

`tests/test_ai.py` 校验连续传跑及规则检索完整性，`tests/test_ai_api.py` 校验写入权限、草稿不落库、SSE 首批资料即时发送、引用编号及并发释放；实际模型结果还需人工核对。

## Drill 循环演示

Drill 战术板的播放栏提供“↻ 循环”开关。编辑者切换后点击保存，队友打开同一链接即可沿用；只读访客也可临时切换本次播放方式。普通战术仍默认播放一次，循环设置不会带入普通战术。备份导出、导入、服务器重启均保留已保存的设置。

循环开启后，末步自动接回首步，并显示当前轮次。队员和盘权首尾一致时连续衔接；不一致的旧 Drill 会明确提示每轮复位，不补画不存在的跑动。暂停、复位和手动切步均可停止播放。切换循环设置支持撤销。

“二人钟摆”用左、右接盘角标及中间回位角标演示：从 O2 已回盘给 O1 的状态起，O2 回中间 → 切左接 O1 传盘 → O1 回中间 → 切右接 O2 回盘。4 步后回到相同站位与盘权，默认循环开启。接盘人持盘等候，出盘者先回位再切出，避免带盘跑动。角标间距为讲解示意，可按训练场地编辑。

```bash
node scripts/verify-playback.cjs
```

该检查跨三个完整循环核对位置、盘权、传盘终点及单次播放停止行为；后端测试覆盖循环设置的共享保存、重启、导入和输入校验。

WFDF 右上角的对话图标用于展开或收起 AI 问答。问答面板从底部滑出，无背景遮罩，展开时仍可操作规则检索；手机使用全宽底部面板，并适配可见视口与底部安全区。点击收起、再次点图标或按 Escape 可关闭面板，切到战术库时也会收起。收起不清空对话，也不中断正在返回的回复；重新展开即可继续查看。条款原文和手势详情仍可独立打开。对话只保留在当前页面内存，刷新后清除。

战术板选中队员或角标时，操作栏显示在上方原有人数栏的位置：队员可设为持盘人、移除或取消选择；角标可改名或移除。人数栏保留原有占位，不因操作栏出现而改变场地大小、位置或比例。取消选择后恢复人数调整；横屏全屏时操作栏位于顶部浮层。选中本身不会修改战术，实际操作仍支持撤销和保存。


## 先整理、确认，再生成战术图

战术 AI 使用 `POST /api/ai/coach` 连续对话整理方案（需要编辑权限），沿用规则助手配置的快速模型，绘图仍使用战术模型。每轮携带最新完整摘要和最多 10 条、合计 6000 字的近期消息，不依赖固定对话轮数。最新明确纠正优先；人数变动后重新核对。信息不足时只追问关键缺项，也可明确选择“先画已明确部分”，缩小到已知连续动作，未确认的轮换或循环不补画。编辑摘要后需再次核对；确认后才调用绘图接口。绘图不合格的具体反馈返回对话，保留已有方案；最多一次自动布局修复，仍不合格不会返回可保存草稿。旧 `/api/ai/outline` 保留兼容。

第二步的 `POST /api/ai/tactic` 只接收教练确认过的文字和明确的 `confirmed: true`，未确认会在调用模型前拒绝。生成时保留已确认的角色映射，优先让起始站位与纵深切入沿场地长边从左向右展开；明确的横向练习、回传与阵型仍按原意绘制。结构校验通过后继续展示图示草稿，由教练在战术板再次检查并保存。两阶段均使用服务器既有模型配置，不引入新的密钥或存储对话。

手机及触屏设备的文本、数字和选择输入均使用至少 16px 字号，保留原生手动缩放，不设置 `user-scalable=no` 或最大缩放限制。`mobile-viewport.js` 仅将输入弹窗与编辑浮层适配到键盘留下的可见区域；编辑浮层不进入场地布局。WFDF 底部面板仍按可见视口定位输入区。验证覆盖手机尺寸、输入实际字号和缩小可见区域；桌面内置浏览器不能代替真机 iOS/Android 键盘测试。


Cut-in Drill 实例测试补充了 AI 布局校验：同队队员在起始和每步结束时不得重叠或过近。图标间距按画图单位检查，不作为真实训练距离要求。若首次生成存在重叠，最多自动要求模型修正一次，同时保留教练确认的角色、盘权、传盘顺序及队列前移；仍不合格则停止返回草稿，并保留原说明供修改。代码不擅自把队员挪到猜测的位置，手动画图接口也不会因此改变既有保存内容。

## 分页式新建流程

新建统一在一个窗口中分步完成：先选择 AI 辅助或手动画图并设置人数。AI 模式依次进入“对话”“预览”，每次只显示当前页；手动模式直接进入战术板。返回上一步保留对话、摘要与人数，改变人数后继续对话以更新方案。页面采用轻量左右转场，并遵循系统减少动态效果的设置。

预览页一次展示一个步骤，可用左右按钮检查全部步骤，再选择进入战术板编辑。预览与生成仍不自动保存到团队库。键盘出现时，新建窗口收起步骤导航和辅助文案，将输入区与操作按钮适配到可见范围；不限制用户手动缩放。

AI 还会拒绝无实际位移的跑线，避免把“原地站住”画成已经完成切入。若描述包含拉开再回切，必须使用不同位置；布局修正最多一次，不能删除已确认动作或改变盘权来绕过检查。

### 长按删除路线与七人站位模板

编辑时，跑动模式长按队员约 650 毫秒，只删除该队员在当前步骤的跑动路线；传盘模式长按飞盘，删除当前步骤的传盘路线。外圈随按压时间显示进度，提前松手、开始拖动、切换步骤/工具、失焦或中断触摸都会取消。飞盘在传盘模式有较大的触控区，也可以从飞盘拖出传盘线。键盘选中相应队员或飞盘后可用 Delete/Backspace 删除路线。删除进入现有撤销栈，保存后才同步到服务器。

手动新建可选竖排 2–5、横排 3–4、区域 3–3–1 起始站位，Drill 仍最多七人。编辑详情里的“7 人站位模板”支持选择已有七人的练习/进攻组或防守组；保留队员 ID、编号、攻防身份和持盘人，重排当前步骤并清除本步路线，其他步骤不变，可撤销。区域模板采用现有三人杯、双侧翼、中路和深区的示意布局。手机套用后返回战术板，便于继续调整。

验证交互与模板：`node scripts/verify-board-editing.cjs`。计时控制器与画面绘制分离；移动阈值按屏幕像素计算，进度圈保持可见尺寸，支持横屏旋转场地。

## 个人看板、头像与训练日期

个人看板从既有记录汇总：个人场均只除以本人有阵容或事件记录的已结束正式比赛场次；训练赛单独查看，不混入正式比赛。个人考勤排除计划中、取消、未来及入队前的训练，无有效训练时显示「—」。待写心得从已参加的比赛与训练中列出，已写心得可回到原场次修改。手机采用四栏底部导航和整页表单，管理员按钮仅在编辑模式可见。

训练新增 `held_on`（实际日期）与 `status`（planned/completed/cancelled）；新建默认计划中。旧训练沿用创建日期并按已完成迁移，历史出勤不丢失。管理员可在训练详情右上角直接点击「修改日期」，调整日期并保存；「训练操作 → 修改训练信息」也可修改名称、日期与状态。调整日期保留出勤、Drill、训练赛与总结，并按新日期重新计算考勤。

队员头像先在浏览器裁剪、压缩为 256×256 JPEG，再通过 `PUT /api/stats/me` 交给服务器独立校验并重编码（仅 JPEG/PNG/WebP，输入最多 2MB、2000 万像素；存储最多 100KB，移除 EXIF）。头像保存在同一 SQLite 的 `stats_avatars` 表中，纳入既有数据库备份，不进入 Git；URL 包含内容摘要以支持缓存。个人资料接口拒绝更新其他队员或考勤、号码等管理字段；服务端校验队员会话，不依赖前端隐藏按钮。

头像处理依赖固定版本 `requirements.txt`（[Pillow 官方发布说明](https://pillow.readthedocs.io/en/stable/releasenotes/)）。本地建议使用 Python 3.10+ 的虚拟环境，执行 `python -m pip install -r requirements.txt`；线上 API 使用 Python 3.12 镜像构建并安装同一版本。`.dockerignore` 仅允许构建说明与依赖清单进入构建上下文，私有 `.env`、数据库、头像和备份均排除。

验证：`python -B -m unittest discover -s tests` 覆盖玩家与管理员权限分离、口令轮换和旧会话失效、上传校验与头像压缩持久化、旧库迁移与日期校验；`node scripts/verify-team-metrics.cjs` 覆盖参赛分母、训练赛隔离、零分母及考勤边界。

队员页上方使用最多两排的横向名单，手机保留下一列预览，支持触摸、触控板和左右键；下方场均表格最多显示六名队员，小屏高度不足时进一步收紧。表格内上下滚动时表头固定，「全部指标」仍可横滑，左侧姓名保留。刷新数据时保留名单与表格当前滚动位置。手机选择框统一字重、箭头留白与触控高度，输入控件至少 16px；顶栏按内容自动增高，避免操作按钮压住搜索栏。训练出勤名单限制可见高度，Drill 选择器的说明独占一行，避免长文本把「添加」按钮挤出屏幕。

训练与比赛共用活动卡片样式（状态、名称、日期、摘要和右侧统计）及详情页四栏导航。训练详情按「训练安排 / 出勤记录 / 训练赛 / 训练总结」切换，比赛按「实时记录 / 本场数据 / 逐分记录 / 赛后总结」切换；桌面与手机行为一致。手机出勤名单独立滚动，保存出勤按钮保留在底部；切换页签不清空尚未保存的输入。

比赛使用独立的 `stats_games.held_on` 日期（API 为 `heldOn`）。新建表单必须选择实际比赛日期；训练赛表单预填所属训练日期，仍可单独调整。管理员可在比赛详情点击「修改日期」，或通过「比赛操作 → 修改比赛信息」编辑。修改日期保留创建时间、逐分记录、比分、状态、录像和心得；列表与近期比赛按实际日期排序。旧库新增空日期列，历史比赛显示「日期未设置」，不把创建时间当比赛日期；兼容旧客户端省略日期的请求，明确传入的日期必须是有效的 YYYY-MM-DD。个人头像与队员登录菜单仅在盘队中心显示，切换工作区保留登录会话。

界面字号集中在 `dist/typography.css`：页面标题 22px（手机 20px）、窗口标题 20px（手机 18px）、分区标题 16px、按钮 14px、正文 14px（手机 15px）、规则与对话 15px（手机 16px）、辅助信息 12px。手机输入框至少 16px，战术板图形文字与图标保持坐标比例。Tiga 字标使用自托管 Oxanium 700 Latin WOFF2（约 7KB，来源 Google Fonts；授权见 `dist/fonts/Oxanium-OFL.txt`），仅用于品牌，字体随版本化资源发布，无运行时外部字体请求。

飞盘用语：全队累计使用「得分」；D 统一称「防守成功」（如拦截、拍落传盘），传盘统计明确为「传盘完成」，阵容统计明确为「上场分数 / 进攻开 / 防守开」。逐分记录使用「本分起始」，事件计数使用「条记录」；没有记录得分结果时显示「未记录结果」，不据此推断对方得分。界面、内置示例和错误提示统一使用「队员」，WFDF 原文保持来源文本。知识库区分 Force（逼防策略）、Mark（防盘）和 Marker（防盘队员）。训练与比赛总结共用全宽输入区、提交按钮与已发布心得间距，输入可纵向调整高度。

## 训练讨论和视频复盘

训练详情的「训练讨论」支持多条评论、头像和回复。训练赛（正式比赛同样可用）的「赛后讨论」上方由管理员添加 B 站视频链接，支持完整 BV/av 链接、BV 号，以及可解析的 b23.tv 短链接；解析失败时提示改用完整链接。其他已有录像链接仍可跳转原站观看。播放器使用 [B 站官方外链播放器](https://player.bilibili.com/)，通过 `p` 指定分 P、`t` 指定初始秒数。仅在进入讨论页时加载，刷新评论保留同一个播放器，离开页面停止播放。

讨论页去掉重复标题和无视频说明，直接展示评论。训练及比赛的讨论标签在有其他人的未读评论/回复时显示小点；进入可见讨论页后清除，后台或被其他窗口遮挡时保留未读。编辑旧评论和自己的发言不触发提醒。已读位置按队员身份、场次保存在当前浏览器，游客单独记录；不跨设备同步，清除浏览器数据后重置。复用现有 8 秒轮询获取新消息。

评论输入区位于评论列表底部，默认一行，随输入最多扩展至四行，超出后在输入框内滚动。第二行提供时间点及发送图标按钮；有可播放视频时才显示时间点按钮。点击「添加视频时间点」，填写如 `01:25`、`1:02:03` 或秒数 `85`，并选择分 P。时间点须按播放器进度手动填写，不自动读取跨域播放器的当前进度。训练讨论可从本次训练的训练赛视频中选择引用。点击已发布的时间点会在页内切换至对应视频和位置，浏览器可能仍需要再次点播放；页面保留在 B 站打开的入口。时间点绑定视频 ID，后来更换视频时旧节点显示不可用，不会指向新录像。

新增讨论接口为 `POST /api/stats/{games|trainings}/{id}/discussion`、`PUT/DELETE .../discussion/{commentId}`；恢复使用 `PUT {restore:true}`。评论写入要求队员会话，添加或替换视频仍要求编辑会话；两者独立。回复只接受同一场次的主评论，不能跨训练引用视频或修改别人的评论。数据库在既有 `stats_comments` 上新增父评论、删除状态与视频引用字段，保留原 ID、内容及作者；旧单人心得 API 保持兼容。头像从当前队员资料读取，已离开名单的作者使用历史盘名与默认头像。

验证：完整 Python 测试覆盖讨论权限、历史唯一约束迁移、评论恢复和视频归属；`node scripts/verify-discussion.cjs` 验证时间格式及播放器参数。组件与页面初始化可运行 `npm install --prefix /tmp/frisbee-discussion-dom linkedom`，再运行 `NODE_PATH=/tmp/frisbee-discussion-dom/node_modules node scripts/verify-discussion-dom.cjs`；该临时依赖不参与部署或运行。
